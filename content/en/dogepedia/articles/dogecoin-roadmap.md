“Roadmap” often implies a single company or lead developer steering a product on a fixed schedule. **Dogecoin is not that.**

Dogecoin is a **community-driven, consensus-based open-source project**. Direction emerges from the people who write code, run infrastructure, build apps, write docs, and use the coin — not from a corporate product plan.

It helps to separate three things that sometimes get mixed together:

| Layer | What it is | Where to look |
|-------|------------|----------------|
| **Dogecoin Core** (the reference node / wallet software) | The “boring base” of the network — consensus rules, P2P, RPC, releases | [dogecoin/dogecoin](https://github.com/dogecoin/dogecoin) |
| **Ecosystem projects** | Libraries, wallets, payment rails, websites, tools built *around* Dogecoin | Community repos, merchants, [ecosystem projects](/dogepedia/articles/dogecoin-ecosystem-projects) |
| **Dogecoin Foundation** | A not-for-profit that supports development and advocacy; **one participant among many** | [Trailmap](https://foundation.dogecoin.com/trailmap/) |

## Dogecoin Core: where software direction is worked out

For **Dogecoin Core** (the software you run as a node or full wallet), technical work is centered on GitHub:

- Code and pull requests: [github.com/dogecoin/dogecoin](https://github.com/dogecoin/dogecoin)
- Planning / project boards: [Core Projects](https://github.com/dogecoin/dogecoin/projects)
- Design discussions: [GitHub Discussions](https://github.com/dogecoin/dogecoin/discussions) (for example consensus and major-release threads)
- Community chat for developers: [r/dogecoindev](https://reddit.com/r/dogecoindev)

Larger changes take more peer review and social consensus — the same pattern other open-source money projects use. Historical **Dogecoin Improvement Proposals (DIPs)** live at [dogecoin/dips](https://github.com/dogecoin/dips); they are not the day-to-day process for every change, but they remain part of the ecosystem’s vocabulary for significant ideas.

If you want to contribute code, start here: [Becoming a Dogecoin developer](/dogepedia/articles/becoming-a-dogecoin-developer).

## Ecosystem projects: changing how people *use* Dogecoin

Ideally, Core stays a **solid, boring foundation**, and creativity happens on top — wallets, payment APIs, bridges, apps, memes, merchant tools. Those projects can change day-to-day experience (speed, UX, tipping, commerce) **with little or no Core change**, if the community adopts them.

That is intentional: Dogecoin should remain a decentralised project with **shepherds rather than rulers**. Ecosystem work stands or falls on merit and usage, not on a single authority’s roadmap.

Examples of where the ecosystem lives today include LibDogecoin, GigaWallet, documentation, and community websites — pick up a shovel and [join in](/dogepedia/articles/how-can-i-help-doge).

## The Dogecoin Foundation Trailmap (not “the Dogecoin roadmap”)

The Foundation participates in the **same open, consensus-based process** as any other contributor. It publishes a **[Trailmap](https://foundation.dogecoin.com/trailmap/)** of projects it is investing effort in and believes help Dogecoin succeed.

Important clarifications:

- The Trailmap is **not** an authoritative plan for Dogecoin consensus rules.
- It is **not** a substitute for Core’s GitHub process.
- It **does** list Foundation-backed work that may sit around Core (tooling, advocacy, ecosystem), which is why mixing “Foundation roadmap” and “Core roadmap” confuses people.

When in doubt: **protocol and Core software → GitHub Core; Foundation priorities → Trailmap; apps and culture → the wider community.**

## Short answer

There is no single corporate “Dogecoin roadmap.” There is:

1. **Core development** on GitHub, with community review  
2. **Ecosystem innovation** on top of that base  
3. A **Foundation Trailmap** for Foundation-led projects  

Much consensus. Such shepherding. **Do Only Good Everyday.**
